# Getting a show into grandMA3 (the MagicQ to grandMA3 direction)

Counterpart of `shw-format.md`. The grandMA3 `.show` file is binary and compressed with MA's own scheme (checked 2026-10-29: entropy 8.0 bits per byte, no known compression signatures, no names in clear), so the converter does not write it. It writes an **import package** (`show.json`, generated GDTF files, `report.md`) and a Lua plugin (`ma3/import_show.lua`) builds the show inside grandMA3 with ordinary commands. What the plugin relies on, and where that knowledge comes from:

## Facts used (grandMA3 2.3 help, shipped offline in `gma3_2.3.2/shared/language/HTML/`, and MA's own plugins)

- **Command line over OSC**: `/cmd` address with one string argument executes any command (`remote_inputs_osc.html`). Needs Menu > In & Out > OSC: Enable Input, and a configuration line (port 8000 UDP) with Receive Command = Yes. The OSC configuration is stored in the show file, not in a settings file, so a new show starts with it off. `scripts/ma3_osc.py` sends such messages; `scripts/ma3_import.py` runs the plugin this way and waits for `result.json`.
- **Exact DMX values**: `Attribute "Pan" At Absolute Decimal16 32768`, `At Absolute Decimal8 128` (`keyword_decimal8.html` and the Decimal16, Decimal24, Hex8, Hex16 pages). That is how every value is set, so the result does not depend on the fixture type's physical ranges.
- **Fixture types**: `Import Library "<name>"` with the command line destination at `ShowData/Patch/FixtureTypes` and the pool's `Source` property selecting the library (`grandMA3`, `grandMA2`, `User`), the way MA's system-test plugin does it (`shared/resource/lib_plugins/systemtests/requirements/gma3internal_fixtures.lua`). GDTF files are read from `gma3_library/fixturetypes` (`ft_import_gdtf.html`). The grandMA2 library ships as 10,507 encrypted `.pxml` files in `shared/lib_fixture_types/grandma2/`, named `manufacturer@model.pxml`.
- **Patching**: Lua `AddFixtures({mode=<DMXMode handle>, amount=1, fid="1", name="...", patch={"1.001"}})` with the command line destination at `Stages/Stage 1/Fixtures` (`lua_objectfree_addfixtures.html`, signature confirmed in the 2.3.2 binary). Fallback: the command recipe of `system_test_helping_functions_patch.lua` (`Store n /NC`, `Assign FixtureType "x" At n`, `Set n Property "FID"/"Name"/"Mode"/"Patch"`). `Patch Fixture 2 3.123` only re-addresses an existing fixture; MVR import is a Patch menu button with no command (`patch_mvr.html`).
- **Storing**: `Store Group n /NC`, `Store Preset pool.no /NC`, `Store Sequence s Cue c /NC`, `Store Sequence s Cue c Part p /NC`, names with `Label`. Preset pools: 1 Dimmer, 2 Position, 3 Gobo, 4 Color, 5 Beam, 6 Focus, 7 Control, 8 Shapers. A MagicQ palette becomes one preset per pool it touches, so a MagicQ beam palette with gobo and focus values becomes a Gobo preset and a Focus preset.
- **Cue timing**: `Set Sequence s Cue c Property "CueFade" 2.5` (the plugin tries `CueFade`/`Fade`, `CueOutFade`/`OutFade`, `CueDelay`/`Delay`, `CueOutDelay`/`OutDelay` and keeps what the console accepts). MagicQ position, colour and beam fades that differ from the intensity fade become cue parts 1 to 3 with their own fade. MagicQ chases become cues with `TrigType "Time"` and `TrigTime` = step time, fade 0.
- **Executors**: `Assign Sequence s At Page p.e` (fallback `Page p` then `Assign ... At Executor e`). MagicQ playbacks 1 to 10 go to executors 201 to 210 of the same page number; groups and palettes on playbacks go to 101 onward.

## What the plugin decides at run time

- Library match: each head in `show.json` carries up to three candidates found by name in the grandMA2 and user libraries (`ma3/libmatch.py`). The plugin imports a candidate, reads its DMX modes through the object tree (`DMXModes`, `DMXChannels`, `Coarse`/`Fine`, the logical channel's `Attribute`) and keeps it only when a mode has the same footprint and, at every MagicQ channel offset, the same byte width and the same attribute family (intensity, position, colour, other). Otherwise the imported type is deleted and the generated GDTF is used.
- The result goes to `result.json` (`counts`, `failed` with every refused command, `info` with the fixture type chosen per head) and `progress.log`.

## Confirmed in grandMA3 onPC 2.3.2 (2026-10-29, spikes driven from this machine)

- **Two ways to drive onPC without touching its window**: OSC `/cmd` (needs the setting in the show) and the **web remote** on port 8080 (on by default here, `EnableRemotes` in `onpc/config/manet_socket.xml`). The web remote connected without a login and its command line executes anything typed into it; `scripts/ma3_web.py` types through a headless Chrome (dev-browser), `scripts/ma3_import.py` and `scripts/ma3_compare.py` pick OSC when it answers and the web remote otherwise. About one second per command, fine for a one-line `Lua "dofile(...)"` start.
- **Fixture type import**: `cd Root`, `cd 'ShowData'.'Patch'`, `Set "FixtureTypes" Source="User"` (or `"grandMA2"`, `"grandMA3"`), `cd 'FixtureTypes'`, `Import Library "<file>.gdtf"` (GDTF from `gma3_library/fixturetypes`) or `Import Library "<manufacturer>@<model>"` (grandMA2 library, no extension). The new type is the last child of `Root().ShowData.Patch.FixtureTypes`. `Import FixtureType Library ...` from the root destination fails. The grandMA2 library answers "Illegal object" until its scan has run once in the session (`Call Library` toggles the library view; the plugin calls it once per source and retries the import once).
- **Reading a type**: `ft.DMXModes` children, each with `DMXChannels` children; `Coarse`, `Fine`, `Ultra` hold the 1-based offsets ("None" when unused), the attribute name sits on the first child of the channel (`LogicalChannel.Attribute`), not on the channel itself. `obj:Dump()` prints every property.
- **Patching**: the command recipe works inside one edit-patch session: `cd 'Stages'.'Stage 1'.'Fixtures'`, `Store n /NC`, `Assign FixtureType <index> At n` (index in the edit pool; names collide), `Set n Property 'FID' 1`, `Set n Property 'Name' "x"`, `Set n Property 'Mode' '<HandleToStr(mode)>'`, `Set n Property 'Patch' "1.001"`, then one `cd Root` for all fixtures. A new show already holds the Universal fixture at index 1. **Leaving the edit patch (`cd Root`) invalidates every handle taken inside it**: a mode handle from a previous session set on a fixture crashed onPC twice (`EXC_BAD_ACCESS`). `AddFixtures()` from a `dofile` chunk returned true and crashed onPC a second later; not used.
- **Selection and values** as two commands: `Fixture 1 + 3`, then `Attribute "Pan" At Absolute Decimal16 16384` or `... Decimal8 128`. The one-line form `Fixture 1 Attribute "Pan" At ...` answers "Not implemented". Verified by `GetDMXValue`: Pan 16384 gives 64/0 on the coarse/fine bytes, Decimal8 values land unchanged.
- **Store**: `Store Preset 2.1 /NC` with the fixture selected keeps only its pool's attributes (position preset from a programmer holding position, gobo and colour came back with position only); `At Preset 2.1` recalls it. `Store Sequence 91 Cue 1 /NC`, `Store Sequence 91 Cue 1 Part 1 /NC` (a part stores the whole activation group, so pan goes with tilt), `Label Sequence 91 Cue 1 "name"`. Properties that worked: `CueFade`, `CueOutFade`, `CueDelay`, `CueOutDelay`, `TrigType "Time"`, `TrigTime`, `Tracking "No"` on the sequence; `Fade` is "Illegal property".
- **Executors**: `Assign Sequence 91 At Page 1.201`, `Assign Group 1 At Page 1.101`. `Assign ... At Executor 1.201` is "Cannot Create Object".
- **DMX read-back**: `GetDMXValue(absolute_address)` (universe 2 address 101 is 613); the two-argument form with a universe returned nil. **Once anything is patched on universe 1, every `GetDMXValue` and `GetDMXUniverse` call returns nil** in this onPC build; universes 2 and up read fine. The comparison therefore runs on a package written with `--universe-offset 1`.
- **Cmd return strings** seen: `OK`, `Failed`, `Illegal object`, `Illegal property`, `Not implemented`, `Cannot Create Object`.
- **Housekeeping**: killing `app_gma3` makes its `app_system` parent respawn it, and `open -a grandMA3` next to a running instance starts a second one that steals the web remote port and has no DMX engine. Quit through the GUI, or kill the whole tree (`grandMA3`, `app_system`, `app_gma3`, `web_daemon`) before relaunching.

## Results

- Demo show (`scripts/demo_show.py`: 2 dimmers, 2 spots, 4 palettes, 2 stacks): imported in 3.7 s, `scripts/ma3_compare.py` reports **13 of 13 cue values equal** between the MagicQ file and what grandMA3 outputs per cue.
- Real MQ50 show (`samples/mq50-zt-ttr-2026.shw`, 48 heads, 23 groups, 75 palettes, 60 stacks, 68 cues): imported in 18 s, **1323 of 1323 cue values equal**. Two fixes came out of the first run: a second dimmer channel in a head must not map to `HSB_Brightness` (it drives the RGB engine; it is now a custom `Dimmer_2` attribute, which grandMA3 accepts from the GDTF), and a cue that holds only the fine byte of a 16-bit attribute takes the head default for the coarse byte.
